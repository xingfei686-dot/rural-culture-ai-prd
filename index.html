01 项目概览

WHY THIS PRODUCT

文化资料很多，
但“找到”不等于“读懂”

地方文化内容往往散落在网页、文章与地方志中。普通用户需要跨来源检索、判断可信度，再把专业叙述转化成容易理解的信息。

“乡村文化通”以自然语言问答作为入口，让用户可以像向一位熟悉当地的讲解员提问，并通过知识检索约束回答范围、标注依据。

目标用户文化旅行者、学生与教师、地方文化爱好者
核心任务快速了解乡村历史、习俗、技艺与文化故事
产品边界文化知识辅助与线索导航，不替代权威考证
02 用户问题

USER INSIGHT

从“搜资料”到“获得可信答案”
中间隔着三道门槛

01

内容分散

信息分布在不同平台和文档中，检索路径长，同一主题难以形成连贯认识。

02

表达有距离

地方志与研究资料术语密集，缺少面向普通用户的解释、背景与延伸线索。

03

可信度难判断

生成式回答可能混淆传说与史实，需要检索约束、来源提示与不确定性表达。

核心用户故事
“当我对一个村落、习俗或传统技艺产生兴趣时，我希望用自然语言快速提问，获得清晰、有依据且能继续追问的解释。”

04 Agent 架构

WORKFLOW & RAG

把一次回答，拆成可控制的产品流程

Workflow 负责“怎么走”，知识库负责“依据什么答”，Prompt 负责“以什么方式答”。

1问题输入用户意图与上下文
→
2问题识别判断主题与检索需求
→
3知识检索召回相关资料片段
→
4答案生成整合、解释与降噪
→
5来源标记提示依据与不确定性

01 / KNOWLEDGE

知识库策略

  • 按“地区—主题—内容类型”组织资料
  • 切分时保留标题、出处与上下文
  • 优先使用可核验、来源明确的材料

02 / PROMPT

回答策略

  • 先给直接结论，再解释背景与关联
  • 区分史实、民间传说与合理推断
  • 材料不足时明确说明，不强行生成

03 / EXPERIENCE

对话策略

  • 识别宽泛问题并主动收窄范围
  • 提供可继续追问的相关主题
  • 保持友好、克制、非说教式表达
05 测试与迭代

BAD CASE LOOP

不只验证“能不能答”，
更验证“答得是否可靠”

测试类型典型风险优化方向
事实型问题年代、人物、地名混淆强化检索依据与来源约束
宽泛型问题回答空泛、信息堆砌先澄清范围，再分层回答
知识库外问题模型补全不存在的细节设置拒答边界与不确定性表达
连续追问丢失上文主体或地区保留关键上下文，校验指代
收集记录异常回答与用户问题
→
归因知识、检索、Prompt 或流程
→
优化补资料、调参数、改指令
→
回归用同类问题复测效果
06 项目复盘

REFLECTION

AI 产品的价值，
不止是接入模型

这个项目让我把 Agent 从“能对话的 Demo”推进到“有知识边界、有流程控制、可持续迭代的产品”。真正影响体验的，不是单次生成有多惊艳，而是知识、检索、指令和测试能否形成闭环。

01从功能出发

把模糊的“文化助手”拆成具体用户任务与回答流程。

02从边界出发

承认资料覆盖有限，用透明表达换取长期信任。

03从迭代出发

用 Bad Case 驱动知识库、Prompt 与 Workflow 联动优化。
